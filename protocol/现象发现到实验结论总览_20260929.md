## 1. 现象发现：研究从哪里开始

### 1.1 起始观察

传统 Event Linking 通常默认输入已经表达了一个事件 mention，然后在知识库内外进行链接或 NIL 判断。Stage1 的审计发现，上游开放网络输入中还存在另一类情况：文本可能包含人物、地点、话题或局部动作，但没有在当前组织政策下前景化一个可组织的目标事件。

因此需要区分三个评价单位：

- `mention`：原始事件链接系统看到的提及；
- `target`：候选目标或知识库实体；
- `item`：作为整体决定是否进入事件组织流程的输入。

候选存在、目标是否在库外、以及 item 是否应被准入，不能直接互相替代。研究起点不是提出一个普通 REJECT 二分类器，而是发现 Event Linking 到下游事件组织之间存在一个任务假设和测量接口缺口。

### 1.2 Stage1 材料

Stage1 将 EventLink-NYT 的 993 个 NIL mention rows 还原为 639 条唯一文本，形成了一个 operational overlay：

- 599 条 EVENT-DESCRIBABLE；
- 40 条 REJECT；
- 分层条件性比例点估计 6.78%，有限总体区间 6.26%--9.39%；
- 40 条 REJECT 对应 62 个原始 NIL candidate mentions。

这个比例只描述经过 EventLink-NYT 候选筛选的材料，不能解释为开放 Web 自然输入流中的 REJECT prevalence。Stage1 还发现，item-level 可组织性标签不能直接改写为 mention-level 的 LINK/NEW/REJECT Gold，因此后续实验必须先固定任务单位和准入政策。

### 1.3 Stage1 的边界

Stage1 证明了受筛选 EventLink 候选池中存在自然 REJECT 现象，并形成了可执行的标注协议。它没有证明：

- 开放 Web 中的真实 REJECT 率；
- 40 条 item-level REJECT 都是 mention-level non-event；
- 现有 linker 一定受到显著下游损害；
- 单一 confidence threshold 一定无法处理问题；
- 图片普遍可以补足文本事件证据。

这些问题进入 Stage2，以“Open-Web Event Admission / Calibration”作为收缩后的主线。

## 2. Benchmark 任务定义

在固定 `WEB-TEXT-ADMISSION-v2` 组织政策下，任务是判断一个 item 是否应被准入事件组织流程：

- `ADMISSIBLE`：当前证据和政策下允许进入组织流程；
- `REJECT`：当前证据和政策下不准入。

`REJECT` 是 operational `NO-ADMISSION`，不等于现实中不存在事件，也不等于原 Event Linking 任务中的 NIL。系统链被拆成候选抽取、检索、资格判断和最终准入动作，并同时记录候选覆盖、解析失败、缺分数和阈值迁移。

Benchmark 的核心不是制造一个更复杂的三分类器，而是使以下问题可测量：

1. 候选存在是否足以决定准入；
2. 检索和语义信号对准入有多少预测性；
3. 开发集阈值迁移到新时段时，Retention--REJECT FAR 如何变化；
4. 测量链失败（无候选、解析错误、缺分数）会不会改变结论。

## 3. 数据选取与证据分层

### 3.1 P0：任务单位与标签对齐校准

- 80 个 item，124 个 mention；
- item 标签为 39 YES、39 NO、2 UNCERTAIN；
- 用于检验 mention、item 和 target 三轴不能直接传播；
- 证据等级：`development`；部分最终裁决有 AI 辅助；
- 不能作为准入系统的独立性能测试，也不能自动生成 NEW Gold。

P0 的作用是固定任务定义，避免把旧 Event Linking 标签直接拼成新的完整链接 Gold。

### 3.2 Web DEV30 / EVAL60：受控方法诊断

- DEV30 用于阈值和开发决策；
- EVAL60 与 Web60 是同一批 60 个 item，不得重复计数；
- EVAL60 最终为 33 `ADMISSIBLE`、27 `REJECT`；
- DEV30/EVAL60 合计 90 个 item；
- Web60 原始 A/B 一致为 51/60，κ=.6932；存在接触声明和 AI 辅助裁决；
- 证据等级：`controlled diagnostic`，不是未接触的独立测试或 prevalence 样本。

候选恢复、历史 replay 和 D1 clean shallow control 都复用这 90 个 item，不能被写成额外独立样本。

### 3.3 D2：新时段 challenge confirmation

- 102 个新 item，来源为 Bluesky Public AppView searchPosts；
- 时间窗：2026-09-22 00:00 UTC 至 2026-09-28 00:00 UTC；
- 12 个固定英文主题查询；
- 与历史 1,029 条记录在 exact source ID、normalized body、external URL、near duplicate 和 content cluster 上均无重叠；
- A/B 包内容集合相同、顺序独立随机，只展示正文、时间和回复/引用/媒体元数据；
- 17 条分歧由人工 C 裁决，最终 Gold 为 57 `ADMISSIBLE`、45 `REJECT`；
- 部分裁决使用有道机器翻译辅助，必须披露；
- 证据等级：`controlled-calibration challenge confirmation`，不是概率样本，不用于 Web prevalence。

D2 是新时段确认集，但不是完整 EXISTING/NEW/REJECT 事件链接 Gold。它确认的是 item-level 准入/校准现象，而不是整个开放 Web 的总体分布。

### 3.4 不能直接相加的历史材料

- 300 条限额检索结果是检索池，不是 300 条同一政策下完整标注的独立测试 Gold；
- Stage1 的 1,762 条 mention/legacy 标签属于旧任务或历史诊断，不能与 item-level admission Gold 等价合并；
- P0 的 80 item、DEV/EVAL 的 90 item、D2 的 102 item 服务于不同证据层，不能简单相加为一个测试集。

## 4. 实验协议

### 4.1 冻结系统和对照

D2 固定评价包含以下方法：

- `bm25_full_top1`；
- `bge_full_top1`；
- `validity`；
- `direct_admission`；
- `clean_linear`；
- `clean_rbf`；
- `original_exact_existing_joint_linear`（Primary）；
- `admit_all` 参考上界/下界基线。

阈值只能来自 DEV，D2 标签不得用于模型、特征、prompt、阈值或超参数选择。所有 102 条必须进入审计分母；无候选、解析失败、缺分数和 `ABSTAIN` 不得静默删除，也不能用 0 或 -20 哨兵替代缺失值。

### 4.2 主要指标

- 分数覆盖率、候选覆盖率、无候选率和命名失败率；
- Admission Retention：被正确保留的 `ADMISSIBLE` / 全部 Gold `ADMISSIBLE`；
- REJECT FAR：被错误接收的 `REJECT` / 全部 Gold `REJECT`；
- 仅在 102/102 有效分数时报告全量 ROC-AUC/AUPRC；
- 2,000 次配对、按 Gold 类别和内容簇抽样的 bootstrap 区间。

区间只解释这个 challenge set，不能外推为 Web 总体区间。

## 5. Stage2 受控诊断结果

在 DEV30/EVAL60 的原始受控诊断中：

- BM25 AUC=.7632；
- BGE AUC=.5466；
- validity AUC=.7357；
- direct admission AUC=.7469；
- 联合线性 AUC=.7969；
- 联合 RBF AUC=.8058；
- EVAL60 的联合线性结果为 19/33 `ADMISSIBLE` 保留、3/27 `REJECT` 误收。

这些结果说明部分检索/语义信号在受控材料上具有预测性，但它们仍是 `controlled diagnostic`，不能直接写成独立测试性能。严格候选恢复和 clean shallow 结果说明测量链会改变分数和覆盖，不能把所有差异都归因于语义能力。

## 6. D2 固定评价结果（F2）

### 6.1 全量分母

- Gold `ADMISSIBLE`：57；
- Gold `REJECT`：45；
- 所有方法均以 102 条为 item 审计分母。

### 6.2 主要结果

| 方法 | 分数覆盖 | ADMISSIBLE 保留 | REJECT 误收 | ROC-AUC / AUPRC |
|---|---:|---:|---:|---|
| `admit_all` | 102/102 | 57/57 | 45/45 | .500 / .559 |
| BM25 | 101/102 | 53/57 | 27/45 | 全量 NA；条件 .741 / .747 |
| BGE | 101/102 | 55/57 | 40/45 | 全量 NA；条件 .672 / .723 |
| validity | 79/102 | 44/57 | 13/45 | 全量 NA；条件 .870 / .894 |
| Direct admission | 102/102 | 46/57 | 10/45 | .868 / .902 |
| Clean linear | 102/102 | 39/57 | 24/45 | .526 / .546 |
| Clean RBF | 102/102 | 35/57 | 9/45 | .793 / .831 |
| Primary 联合线性 | 79/102 | 40/57 | 10/45 | 全量 NA；条件 .770 / .822 |

### 6.3 覆盖和失败

- 总候选覆盖：79/102（77.45%）；
- 生成状态：93 OK、6 INVALID_SPANS、3 INVALID_JSON；
- 失败计数：9 个解析失败、0 个生成失败、0 个检索失败、0 个重排失败；
- Primary：79 条有效，16 条 NO_CANDIDATE，4 条 INVALID_SPANS，3 条 INVALID_JSON；
- Primary 全量 AUC/AUPRC 必须记为 `NA_NOT_FULL_COVERAGE`，条件 AUC 不能替代全量 AUC。

### 6.4 结果解释

Primary 在新时段数据上没有显示相对优势：它在同样 10/45 的 REJECT 误收下只保留 40/57，而 Direct admission 保留 46/57。F3 的成对差异区间跨 0，因此不能进一步宣称 Direct 已获得统计确认的总体优势。

科学上真正稳定的结果是：

1. 候选和解析覆盖本身是准入性能的一部分；
2. 训练/开发阶段的联合信号收益不能直接视为新时段收益；
3. 在相同误收约束下，不同准入链的保留率存在明显取舍；
4. 当前数据不支持“Primary 已经优于简单准入基线”的方法结论。

## 8. 最终 benchmark 贡献

当前最可辩护的论文贡献是一个**诊断型 Open-Web Event Admission / Calibration benchmark**，包括：

1. 一个明确区分 item、target 和 mention 的任务定义；
2. 一个把候选抽取、检索、资格判断和准入动作分开的测量协议；
3. 一套同时报告 Retention、REJECT FAR、覆盖率和失败状态的评价指标；
4. 一组从开发、受控诊断到新时段 challenge confirmation 的证据分层；
5. 对候选-准入脱节、阈值迁移和测量链失败的实证诊断。

这是一篇现象和 benchmark 论文，而不是一个已经证明有效的 SOTA 方法论文。Primary 的负结果不是需要隐藏的失败，而是说明现有准入链在新时段数据上仍有覆盖和校准问题，并为 benchmark 的必要性提供动机。

## 9. 必须删除或降级的主张

正文、摘要和标题不得声称：

- 已完成完整 `EXISTING / NEW / REJECT` 三动作链接 benchmark；
- D2 代表开放 Web 的概率样本或 prevalence；
- Primary 在独立集上优于 Direct admission 或 clean control；
- Primary 的条件 AUC 是全量独立集 AUC；
- 已证明真实部署成本、下游伤害或普适阈值不稳定；
- 已证明多模态信息或新模型是必要的；
- 历史 300 条、1,762 条 mention、P0、DEV/EVAL 和 D2 可以合并为一个同质测试集。

## 10. 写作结论

最终结论应写成：

> 在开放网络事件组织中，候选检索并不等价于 item 准入。通过区分 item、target 和 mention，并将候选覆盖、准入判断和阈值迁移纳入同一 benchmark，可以观察到开发阶段的信号收益在新时段数据上受到候选/解析失败和校准迁移的限制。现有证据支持一个边界清楚的准入诊断 benchmark，但不支持完整三动作链接、Web prevalence 或某一联合模型的普适优势。

至此实验阶段关闭，进入稿件撰写和投稿适配。后续若需要更大规模、更多来源或完整三动作 benchmark，应作为独立的新项目，而不是回写本稿的实验范围。
